# 今日晨报产品规格

阶段二初稿，供人工整体审查。规格以用户和 API 调用方能观察到的行为为主。目标、范围和成功条件见 [GOALS.md](../../GOALS.md)，现行业务依据见 [PRD](../../../../Docs/PRD.md)，实现现状见 [模块架构](../../ARCHITECTURE.md)。总体建设范围由 [PLANS.md](../../PLANS.md) 维护。技术方案与任务执行记录分别归后续 Design Docs、ExecPlan。

| GOALS.md 业务目标 | 规格 | 覆盖范围 |
| --- | --- | --- |
| 快速掌握资讯 | [资讯获取与阅读](news.md) | 来源、收录、缺失提示、开篇速览及正文 |
| 回顾与行动 | [个人回顾与行动建议](personal-review.md) | 个人数据、证据边界、回顾、建议与模型异常 |
| 控制生成 | [生成、重新生成与重新组装](report-generation.md) | 日期、触发、输入复用、发布条件 |
| 回看与收藏 | [历史晨报与新闻收藏](history-and-favorites.md) | 默认报告、历史版本、收藏、备注与重点 |
| 了解进度与停止 | [任务进度与停止](run-progress.md) | 运行状态、错误、停止、重复提交与中断 |

各规格以 **A 已确认规则**、**B 已确认变更**、**C 当前实现**、**D 待确认**标识依据。此次核查未找到获明确批准的 V3 新业务行为。GOALS.md 中对依据透明度、可用性和诊断性的改进方向已落到相关验收场景。具体体验变更和承诺在人工审查中确认。

接口均以 `/api/morning` 为前缀。除另有标注，接口表记录当前可核实的对外契约，用于评估兼容性。业务错误沿用宿主的 `detail.code` 与 `detail.message`。用户可观察的校验、诊断及评估要求随功能列出，评估样本、评分门槛和技术选型留待后续确认。
