# 生成、重新生成与重新组装

## 目的与范围

用户在每天开始时可获取一份可读报告，并可根据需要重新采集与分析或仅更新组装结果。对应 GOALS.md 的当期生成及「控制与回看」。运行状态和停止规则见[任务进度](run-progress.md)，版本选择见[历史报告](history-and-favorites.md)。

## 场景与规则

| 操作 | 输入与前提 | A 已确认结果 |
| --- | --- | --- |
| 定时生成 | 调度启用，默认北京时间 08:30，目标为当日 | 按现行来源与个人证据规则生成当期报告，并可观察发布结果。 |
| 重新生成 | 用户发起，默认当日，可由接口指定报告日期 | 生成新的分析结果。符合当期策略且覆盖完整的资讯可复用，缺失或策略变化时补采。 |
| 重新组装 | 指定一个已发布版本，且具备可用的已保存组装输入 | 复用该版本的资讯与分析，只组装与发布。无新采集、当前个人数据读取或模型调用，用量为零。前置阶段显示复用。 |

生成可在[资讯缺失](news.md)和[个人证据缺口](personal-review.md)场景按已确认规则给出明确提示与可用内容。成功发布产生同日新版本，历史版本仍保留。输入缺失的重新组装返回错误并提示重新生成。失败或成功停止的任务不得替换可读的成功版本。

## 输入输出与异常

**C 当前对外契约。**

| 接口 | 输入 | 结果或错误 |
| --- | --- | --- |
| `POST /regenerate` | JSON 对象，可选 `report_date`，语义为北京时间自然日，省略或空值使用当天 | 202，返回 `run_id`、`status: pending`，现有响应还带兼容用 `mode: reuse`。 |
| `POST /reassemble` | JSON 对象，必填整数 `version_id` | 202，返回 `run_id` 和 `status: pending`。版本不存在或未发布返回 404，缺组装材料返回 409 `assembly_input_missing`。 |
| `POST /runs/collect`、`POST /runs/generate` | 查询参数可选 `report_date`，生成另有 `mode` 兼容参数 | 202，返回任务 ID、报告日期和待执行状态。单独采集不发布报告。两个接口目前没有同名的主页面操作。 |

生成与重新组装共用任务互斥，冲突为 409 `task_conflict`。202 表示任务已接受，最终结果通过进度与报告读取确认。无可组装报告时页面禁用重新组装。当前主页面按主阅读区报告 ID 请求组装，历史弹窗只提供阅读与下载，按历史版本组装可通过 API 完成。

## 验收

- 启用定时生成后以固定北京时间验证当期报告。手动重新生成覆盖资讯完整、缺类以及策略变化场景，检查是否复用或补采，以及报告日期和版本归属。
- 为指定旧版准备已保存输入，验证后续个人数据和资讯变化不进入重新组装结果。无需模型或新采集，前置阶段标记复用，用量为零，旧版内容仍可读取。
- 提交不存在的版本、缺组装材料和冲突的生成请求，观察明确错误及原有版本保留。验证历史日期的重新组装结果不替换更晚日期的默认晨报。
