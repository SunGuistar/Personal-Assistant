# 个人回顾与行动建议

## 目的与范围

让用户获得最多三条今日建议，并能展开核对各条建议的依据。对应 GOALS.md 的「回顾与行动」。

## 场景与规则

**B 已确认的 V3 变更（2026-11-24）。** 新生成报告的个人部分只展示「今日建议」，最多三条，每条附可展开的依据。个人进展仅在支撑建议时作为依据展示。零条建议时保留小节，区分依据不足、数据读取缺口和分析失败。已发布的历史正文沿用原内容。

- 展开依据时展示生成当时的最小记录摘要，包括相关任务或计划等记录的名称、与判断有关的状态或时间，以及它如何支撑建议。源记录后续变更时，已发布版本仍展示生成时的依据。
- 部分个人来源缺失时，若其余记录足以支撑建议，仍可发布建议，并说明缺失的来源。判断行动或优先级所必需的依据缺失时，保留小节并说明原因。
- 按固定生成时间确定报告日。昨日完成事项的取证窗口为北京时间报告日前一天 00:00（含）至报告日 00:00（不含），取代原 08:00 分界。当前待办和长期计划仍可作为今日建议的依据。
- 建议须事实正确、依据可核对。形成建议时应综合长期计划、每日计划和相关社区信息，并可只读取得「重要信息」与「随手备忘」。每条建议明确选择一种去向：加入每日计划、加入长期计划或加入随手备忘。针对已经验证且会反复使用的验收规则，建议加入每日计划。「重要信息」只作为输入，禁止作为建议去向。晨报沿用个人库只读约束。
- 每日计划承接明确可安排的行动；长期计划承接需要持续推进或分阶段完成的目标；随手备忘承接值得保留、尚未决定是否或如何执行的线索。已有事项可用作依据，优先寻找它尚未覆盖的具体下一步。无值得新增的内容时允许零条建议。
- 长期计划处于搁置状态、每日计划仍有相关待办，且本次记录没有明确恢复依据时，可建议在每日计划添加一项用于确认原待办是否继续的行动，并在展开依据中说明两条记录的冲突。
- 晨报显示各条建议去向，由用户自行前往对应模块添加。
- 建议按推荐优先级排列，多条建议可以推荐加入同一模块。条数由实际可提出的建议决定。
- 既检索已采集的资讯标题，也以类似向 GPT 问询的方式实时检索公开社区信息，社区查询不限定预设站点清单。建议使用社区资料时，在展开依据区显示可核对的来源链接，并说明它与个人计划的相关性。热门内容须结合个人计划判断相关性。
- 对外社区查询仅发送从相关任务概括出的公开主题。个人计划、重要信息、随手备忘原文以及私人标识不作为社区搜索请求内容；它们用于晨报内部判断结果是否相关。
- 两种检索均未取得相关线索时，仍可依据个人记录给出建议。展开依据时区分未找到相关线索与检索失败，并说明原因。
- 事实错误检查仅对照晨报系统提供的信息，包括本轮个人记录及已采集的资讯标题。主动社区检索返回的信息核对引用和相关性，保留来源链接和相关性说明，无需独立验证外部说法。评估也检查依据和行动是否明确。有候选建议时，「今日建议」展示最终候选。仍有事实错误时，正文仅在对应建议显示「评估发现事实错误」，可展开的依据区展示具体原因。没有取得通过结论时，同时展示对应建议的评估状态与原因。未生成候选时，沿用零条建议的原因提示。候选可单独满足[报告发布条件](report-generation.md)。
- 一次评估检查整组候选，并逐条给出结论。基础评估次数按整次生成计算，不随候选条数相乘。发现任一条有事实错误，按一次评估触发事实错误追加规则。
- 本次任务已取得的用户输入冻结。运行期间修改源记录，不改变本次生成和评估使用的输入。下一次手动生成按[材料复用规则](report-generation.md)重新取得有变化的部分。候选建议可以依据同一份冻结输入修正，再按已确认的追加次数规则评估。
- 多轮评估意见不同时，以最终候选仍存在的问题确定展示结论。尚未解决的已确认事实错误，继续显示「评估发现事实错误」，具体原因放入展开依据区。修正后复评通过的，使用复评结论。修正后未取得复评结论的，仍发布最终候选并显示「未取得通过结论」。
- 前端提供评估强度「轻（默认，1 次）」「中（5 次）」「重（10 次）」。强度只决定基础评估次数。事实错误修正次数与基础评估次数分开计算；发现事实错误时默认追加一次评估，因事实错误追加的评估每次生成最多 3 次。所有评估总次数上限仍为 15 次。各档采用相同的评估标准。调用异常沿用[通用运行规则](run-progress.md)。
- 各档首次评估和后续评估沿用同一标准。后续可从不同角度检查，发现问题时可退回候选并要求处理。生成期间显示本次任务的评估强度并锁定选择。任务结束后重新打开页面时恢复轻档。

- **A 授权与质量基线。** 已配置的个人数据源只读，阅读附件仅使用已取得的元数据；历史晨报与历史建议不作为个人决策依据。每条建议有本轮个人依据和明确动作，适用时说明前置条件。已完成事项、多个独立行动捆绑、无据的耗时或收益都属于应处理的质量问题。
- **A 异常。** 个人数据读取失败时披露缺口。非法模型输出或不支持规定的 JSON 模式时明确失败或降级，并遵守换模授权。可读候选经事实核对发现问题时，按 V3 规则展示候选和评估结论；无有效候选的非法输出按分析失败处理。

## 输入输出与兼容

**B V3 对外变更。** 退役 `GET /personal_context`，旧调用不再返回个人上下文。晨报生成继续通过已配置的只读个人库取得本次输入，已发布报告仍可查看保存的依据。

**B V3 建议读取。** 报告按发布版本返回唯一的「今日建议」小节。结果为零至三条，逐条可读取行动、去向、展开依据及适用的评估状态与原因。零条时可读取原因。旧报告按发布内容阅读，不以当前记录补写旧依据。

**C V2 对照。** 旧报告可能包含独立的「我的昨日」及至多一条建议。旧上下文查询与实际生成使用不同的读取入口，其历史结果不代表某次生成的依据。

## 验收

V3 新报告仅展示「今日建议」及可展开的依据。零条建议仍显示小节及对应原因。旧报告按已发布内容显示。

- 发布带依据的建议后修改源记录，重新查看同一版本，展开区仍展示原依据摘要。
- 在评估期间修改任务状态，验证本次候选修正和评估仍使用原始任务状态，下一次手动生成读取变更后的状态。
- 模拟首轮通过、后续发现事实错误，分别核对错误仍存在、修正后复评通过、修正后未取得复评结论时的逐条展示结果。
- 以 11 月 25 日 07:00 为生成时间，验证 24 日 23:30 的完成事项可作为昨日依据，25 日 00:30 的完成事项不计为昨日进展。
- 用与个人计划相关和无关的热门内容验证资讯标题检索与社区搜索，确认建议依据能说明社区信息与个人计划的具体关联。
- 验证每条建议选择且仅选择一个允许的去向，已验证的可复用验收规则推荐加入每日计划。「重要信息」可作为依据，不能作为去向。建议引用社区资料时，展开区显示可核对的来源链接。
- 分别验证明确可安排的行动、跨日目标、待定线索的推荐去向。已有同类事项时，检查建议提供额外的具体行动，无增量时允许零条。使用带私人内容的隔离测试记录，验证对外社区查询只包含概括后的公开主题。
- 模拟长期计划搁置而当日仍有相关待办，验证候选可以建议确认原待办是否继续，并展示冲突依据。
- 分别模拟未找到相关外部线索和外部检索失败，验证在个人依据充分时仍可给建议，展开区展示对应原因。
- 分别模拟无关来源缺失和关键依据缺失，核对前者可展示有证据的建议并说明缺口，后者显示零条建议及对应原因。
- 验证前端默认轻档，支持选择中档和重档。覆盖候选直接通过、修正后通过、仍有事实错误和未取得通过结论。后两种情况下，有候选的已发布报告同时展示候选及评估结果。
- 生成期间持续显示本次评估强度并禁止修改。模拟评估发现事实错误，验证增加一次评估，因事实错误累计追加最多 3 次，总次数不超过 15。验证后续检查发现问题时可退回此前通过的候选。

- 同时提供窗口内已完成、窗口外完成、未完成及无完成时间的记录，验证只有窗口内且有完成证据的记录可作为昨日完成事项的依据；新报告不渲染独立回顾小节。
- 提供超过三条候选行动及缺少个人依据的场景，检查结果为零至三条，且各条都明确对应去向。不为填满三条而补充内容。
- 用三条建议验证同一去向可以重复、结果按优先级排序。选择中档时，基础评估按整组执行 5 次；其中一条有事实错误时，仅该条显示对应标记。
- 分别模拟与晨报提供的信息冲突、仅社区检索结果的说法待核实，验证前者纳入事实错误检查，后者保留来源链接和相关性说明。
- 分别模拟个人库不可用、可读候选引用错误、无有效候选的非法输出及供应商拒绝 JSON mode。核对缺口、逐条评估提示或分析失败的区分，并按报告发布条件处理。调用退役的个人上下文入口，验证不返回个人记录。
- 建议验收检查证据能否回溯、事实与推断是否可区分、社区引用与任务是否相关、行动是否明确、去向是否符合其用途。按低、中、高档验证整组评估次数采用已确认的口径。
