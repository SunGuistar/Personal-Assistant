# 个人回顾与行动建议

## 目的与范围

让用户从晨报了解昨日的可靠进展，识别待确认事项，并在个人依据充分时得到今天可执行的一条建议。对应 GOALS.md 的「回顾与行动」。

## 场景与规则

- **A 授权输入。** 生成只读访问已配置的个人数据源，使用本轮任务、计划、重要信息、备忘、阅读记录和可用元数据。阅读附件正文不作为已取得的证据。回顾窗口为北京时间前一日 08:00（含）至报告日 08:00（不含）。建议可以参考本轮回顾和分析。新闻、历史晨报和历史建议不作为个人决策证据。
- **A 我的昨日。** 仅在记录能证明事项于窗口内完成时标为「事实完成」。对趋势、判断或疑问使用「AI分析」，疑问与信息缺口明确保留待确认含义。条目平铺展示短标题与注解，有详细内容时可展开。证据关联应能核对到实际记录，文字结论还须与记录内容一致。
- **A 今日建议。** 最多发布一条最值得执行的建议。建议须有本轮可靠个人依据，给出明确下一步，适用时说明前置条件。不要把多个独立行动捆绑，也不要把已完成事项当作待办。无依据的时间或收益不予陈述。个人依据不足时允许零条，并向用户说明。
- **A 异常。** 个人数据源无法读取时披露缺口，不据此断言用户没有进展。回顾输出缺失或证据、格式非法时说明原因，只保留已有完成事实。建议分析失败时明确提示失败，不能当作正常的「暂无建议」。模型不支持规定的 JSON 模式时给出明确失败或降级结果，遵守切换授权。

## 输入输出与兼容

个人部分随发布版本返回。用户侧可核对的回顾内容包括标题、注解、类型及可用的细节。建议为零或一条，包含行动、依据和下一步。缺少可信信息时允许信息缺口提示。旧报告仍可读取，既有证据不足时可缺少结构化细节，不用当前个人记录补写过去。

**C 当前接口。** `GET /report` 提供 `content_md` 和可用的 `sections.yesterday_content` 等结构化内容。`GET /personal_context?report_date=YYYY-MM-DD` 使用宿主注入的数据会话，日期省略时为北京时间当天，返回窗口及任务、计划和重要信息列表。该查询的范围和数据来源与实际生成输入不完全相同，不能据此认定某次报告取得的证据。

## 验收

- 同时提供窗口内已完成、窗口外完成、未完成及无完成时间的记录。只有窗口内有完成证据的事项标为「事实完成」。
- 分别提供多个可候选行动、完全缺少个人依据及仅有新闻或历史报告作为依据的场景。结果不超过一条，保留项可对应到本轮记录且下一步可执行，缺证据场景允许零条。
- 模拟个人库不可用、错误证据引用和非法模型输出，检查缺口或失败提示，以及仅保留可核对的完成事实。模型输出评估看证据忠实度、事实与推断区分、建议相关性和可行动性。
