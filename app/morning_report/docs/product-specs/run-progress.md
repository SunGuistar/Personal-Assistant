# 任务进度与停止

## 目的与范围

用户和调用方能区分任务已提交、正在处理、部分缺失、停止和完成，并能理解失败原因。对应 GOALS.md 的「控制与回看」、运行可观测性与恢复要求。业务触发和发布规则见[生成规格](report-generation.md)。

## 场景与规则

- **A 任务概况。** 提交后通过任务 ID 跟踪进度。进度应反映已完成、进行中、待处理及复用的工作。采集缺失有警告与原因，重新组装的前置工作显示复用。长期未更新提示与实际失败分开。
- **A 停止与互斥。** 生成与重新组装共用互斥和停止入口。用户可停止指定任务，界面应区分请求停止和确认停止。停止保留已完成的阶段记录与已有历史，未完成报告不应作为成功结果发布。
- **A 异常。** 来源、模型、取消和进程中断须有可观察的状态或明确的降级结果。故障信息和诊断中保护密钥、个人内容和完整模型消息。可按约定重新提交或恢复，保留已发布结果。自动恢复的范围和承诺待确认。
- **C 当前行为。** 请求停止后可能先显示“正在停止”。任务已结束时重复停止返回已有终态，停止请求与自然完成竞争时可返回自然完成结果。运行中部分步骤失败有时仍可发布降级报告。当前重启对待执行和运行中任务标记失败，运行中的阶段标记中断。停止中状态未被同一恢复规则覆盖。

## 输入输出与状态

**C 当前任务级状态。**

| 状态 | 调用方可观察的含义 |
| --- | --- |
| `pending`、`running`、`stopping` | 等待处理、处理进行中、已请求停止。均为活动状态。 |
| `success`、`degraded` | 正常结束、有明确缺口的结果。是否存在发布版本以报告接口为准，采集任务成功也可无报告。 |
| `failed`、`cancelled` | 失败、已确认取消。 |

阶段状态独立，可携带概况、原因、时间、耗时和非敏感计数。警告或复用阶段可计入已完成阶段数。诊断不把长期无更新直接转成失败。

| 接口 | C 当前输入与输出 |
| --- | --- |
| `GET /progress?run_id=…` | 必填整数任务 ID，返回 `run`、`active`、`stages`、`recent`、完成数和总数、时间及 `seq`。未知 ID 返回 404。 |
| `GET /progress/active?report_date=…` | 日期省略为北京时间当天。按日期返回活动生成任务或最近一条生成记录。无记录时 `run: null`、`active: false`、阶段和动态为空。 |
| `GET /progress/stream?run_id=…&after_seq=…` | 服务端事件流，必填任务 ID，可选序号，默认 0。更新携带快照，终态有 `done` 和最终任务状态。未知任务返回 404。 |
| `POST /runs/{run_id}/stop` | 指定任务 ID，返回任务状态，重复请求可附说明。未知 ID 返回 404。 |
| `GET /status`、`GET /runs`、`GET /runs/{run_id}/logs`、`GET /usage` | 当前提供晨报状态、运行列表、任务日志及用量。用量可按 `run_id` 查询，返回项目和汇总，无记录时为空且汇总为零。 |

当前按任务类型判断互斥，生成与重新组装跨报告日期也会冲突，而页面活动查询默认仅查当天。接口冲突返回 409。生成结果不可用时保留上个已发布版本。用户取消停止确认时，页面不应发出停止请求。

## 验收

- 提交生成或组装后可用 ID 读到同一任务；刷新页面或恢复连接后能查到最新状态。空状态、未开始、复用和告警可辨。
- 在已有活动生成时提交组装，观察明确冲突。重复停止、自然完成竞态或未知任务均可区分，并核对现有历史不受影响。
- 模拟来源和模型故障、进程中断及长时间无更新，检查状态、原因及隐私保护。按获准的恢复规则验证重新提交后可观察到新任务，不将已有历史误认为本次产出。
