# 今日晨报｜完整执行流程 V1.4

> 更新日期：2026-11-10  
> 定位：V2.0 晨报的端到端产品执行逻辑，基于 V1.3 + D01 方案 + DeepSeek 专项验证结果修订，不是代码级接口设计。  
> **V1.4 核心变化：彻底删除每四小时资讯采集，国内、国际、AI 三类资讯统一每天北京时间 08:00 获取一次。** 此规则覆盖 D01 中“国内/国际仍每四小时采集”的旧规定。

## 一、总原则

- **时间窗口：** 前一天北京时间 08:00 至当天 08:00，即 `[昨天 08:00, 今天 08:00)`。
- **启动时刻：** 每天 08:00 启动正式自动晨报任务，随后采集、处理、生成；并非要求 08:00 前就完成报告。
- **采集频率：** 国内、国际、AI 资讯均为每日一次逻辑采集轮次。分页、限流重试、故障补采和手动重新生成时的补齐，不构成独立周期性采集。
- **数据隔离：** 原个人助手数据库只读；晨报模块使用独立 SQLite 与 Qdrant。
- **Agent：** 固定调用技术研究、目标分析、建议三个 Subagent；前两者并行，建议后置。
- **安全门槛：** 必要索引完整才能进入 Agent；严重事实错误、主编失败则不能发布。

## 二、完整流程

```text
【每天北京时间 08:00：唯一常态采集 + 主报告生成】
    │
    ├─ 0. 建立运行记录 / 确定固定时间窗口
    │     ├─ window_start = 昨日 08:00
    │     ├─ window_end   = 今日 08:00（不含）
    │     └─ 清理过期阶段缓存，创建本期唯一运行标识
    │
    ├─ 1. 并行获取本期资讯（Tool；每天一次逻辑轮次）
    │     ├─ 国内新闻：从已确认可用的来源检索固定窗口
    │     ├─ 国际新闻：从已确认可用的来源检索固定窗口
    │     └─ AI 技术资讯：AIHOT REST API 精选列表
    │           ├─ 必要时分页获取完整候选
    │           └─ 热点榜（通过实测后）作为辅助线索
    │     ├─ 统一时间过滤、记录来源与原始链接
    │     ├─ 保守去重、识别事件新进展、必要原文核查
    │     └─ 来源异常可记录缺口并有限重试，不编造正文
    │
    ├─ 2. 持久化 + 必要 Qdrant 索引检查（Tool）
    │     ├─ 国内/国际资讯 → 晨报 SQLite
    │     ├─ AI 资料 → 授权范围内持久化 + Qdrant 技术资讯 Collection
    │     ├─ 历史晨报 → SQLite 正式版本 + Qdrant 历史晨报 Collection
    │     ├─ 复用有效 Embedding，不每日全量重建
    │     └─ 必要索引失败 → 阻塞进入 Agent，修复后重试
    │
    ├─ 3. 冻结快照 + 读取个人上下文（Tool）
    │     ├─ 冻结本期新闻、索引与上下文版本
    │     ├─ 只读提取有时间证据的昨日活动、每日/长期计划
    │     ├─ 读取晨报独立 Memory（资讯/行动偏好等）
    │     └─ 不在此步骤预先做历史语义检索
    │
    ├─ 4. 两个普通 LLM 分析节点并行
    │     ├─ 资讯分析：重要性、兴趣匹配、事件排序与初步摘要
    │     └─ 个人分析：昨日回顾、计划进展及证据缺口
    │
    ├─ 5. 固定三个 Subagent
    │     ├─ A 技术研究 ───────────────┐
    │     │   技术变化、影响、原始证据 │ 并行
    │     ├─ B 目标分析 ───────────────┘
    │     │   昨日活动、长期目标、Memory
    │     └─ C 建议（A/B 完成或明确终态后）
    │         综合上游结果，生成 0—3 条有依据的建议
    │     ※ 三者共用 RAG Tool：Qdrant Dense/BM25 混合检索；
    │       需要时启用 Query 改写/Rerank，失败可退回基础检索
    │
    ├─ 6. 主 Agent 整合中文晨报
    │     ├─ 开篇速览（整体总结）
    │     ├─ 重要资讯（国内/国际：标题+摘要；AI：标题+摘要+评价）
    │     ├─ 我的昨日（仅陈述有依据的事情）
    │     ├─ 今日建议（0—3 条，允许没有）
    │     └─ 来源、时点与信息缺失说明
    │
    ├─ 7. 事实与引用校验
    │     ├─ 新闻出处、发布时间、重复事件与引用
    │     ├─ 昨日活动及计划变化证据
    │     └─ 严重错误 → 阻塞发布
    │
    ├─ 8. 独立质量评价 API
    │     ├─ 仅输入最终晨报正文
    │     ├─ 五维分数 + 综合分 + 一段评价
    │     └─ 评价失败标记未评价，不阻塞通过事实校验的报告
    │
    └─ 9. 发布与存档
          ├─ SQLite 保存正文、来源、版本、评价和执行日志
          ├─ 发布前端：晨报正文 / 质量评价 / 历史晨报
          ├─ 成功报告分块，增量更新历史晨报 Qdrant 索引
          └─ 保存 Token、缓存、费用、耗时、故障及索引状态
```
