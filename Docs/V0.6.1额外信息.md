## 三、技术架构参考（不属于用户界面设计）

### 3.1 职责划分

| 组件 | 规划用途 | 数据边界 |
| --- | --- | --- |
| **现有个人助手 SQLite** | 读取任务、长期计划、阅读、重要信息、备忘及可用活动证据 | **只读**；不做迁移、不写入、不更改历史 |
| **晨报独立 SQLite** | 国内/国际新闻、来源元数据、报告/版本、阶段缓存、日志、评分、费用 | 独立写入与备份；保存来源及快照标识 |
| **Qdrant Server：技术资讯 Collection** | 符合许可的 AI 技术资料及索引，供混合检索和历史关联使用 | 持久化，模型/文本变化时维护索引一致性；不能把不可授权全文当作永久资料 |
| **Qdrant Server：历史晨报 Collection** | 按事件/总结/建议等语义单元保存检索片段 | 正式晨报全文及版本仍以独立 SQLite 为权威 |
| **LangGraph** | 固定工作流、并行阶段、状态、分支和断点恢复 | 图内状态与跨运行阶段缓存分开管理 |
| **LangChain / Tool Calling** | 三个固定 Subagent 和统一历史检索工具 | Tool 返回可追溯证据，不让 Agent 绕过入库与索引流程 |
| **FastAPI + 现有 PC 前端** | 晨报模块、历史页面、状态与实时日志 | 与现有个人助手集成，不另建独立门户 |

后端采用**确定性工具链＋固定工作流＋三名有工具能力的 Subagent**。新闻获取/清洗/索引/事实边界属于工具与程序负责的环节；需要综合判断的分析交由模型/Agent。无需因本次优化引入 Redis、Elasticsearch 或新的 Agent 角色。

## 四、资讯来源的技术细节和证据边界

### 4.1 AIHOT：确定性 REST 获取，不必安装 Skill

根据用户在 Windows PowerShell 提供的真实响应：

- `GET https://aihot.news/api/v1/agent/latest` 返回供 Agent 阅读的 Markdown，不作为程序化采集主入口。
- `GET https://aihot.news/api/v1/items?mode=selected&window=24h&limit=2` 返回 JSON，具有 `items`、`page.hasMore`、`page.nextCursor`；单条含 `id`、`title`、`summary`、`publishedAt`、`discoveredAt`、`source`、`links.original` 等字段。
- `GET https://aihot.news/api/v1/selected/snapshot?limit=2` 返回快照分页和同步游标，但**并非最近 24 小时列表**：实测数据可包括很久之前的文章。

V2.0 初期首选 **`/api/v1/items` 精选查询**。按页取完整候选、根据发布时间本地过滤；热点接口经独立实测后才作为补充线索。每日一次是**一次逻辑采集**，不意味着只有一条 HTTP 请求，也不意味着必须启用完整精选 Snapshot / Changes 镜像同步。

**关键区别**：`publishedAt` 是用于晨报窗口判断的原始发布时间字段；`discoveredAt` 仅表明聚合方发现时间。滚动 `window=24h` 可能受查询时点及平台时间线规则影响；失败晚于 08:00 重试时应选择能覆盖原始窗口的查询范围，再做本地 `[start, end)` 过滤，避免漏掉窗口起点新闻。

从聚合方取得的摘要、评分和推荐理由是**候选资料**，不是事实证明，也不是第三方全文的永久使用授权；需要保留必要元数据、原始链接和更正/撤回处理能力。

### 4.2 国内、国际：新浪点击榜为主，中新网精选补充

2026-11-11 用户确认替换全量归档方案：

- 新浪榜单页面公开使用 `https://top.news.sina.com.cn/ws/GetTopDataList.php`，国内为 `news_china_suda`，国际为 `news_world_suda`；每类请求前 20 条，保存排名、榜单数值、请求日期、实际榜单日期及获取时间。
- 请求日期不能替代返回日期；仅接受当日或前一日榜单，前一日必须标记降级，超过一天或未来日期视为不可用。文章归属仍独立按 `[前一天08:00, 当天08:00)` 判断。
- 中新网仅访问首页、时政及国际频道精选页；每类候选详情请求最多 15 次，最多补充 5 条，不再抓取全量归档。页面结构变化或来源失败需记录覆盖缺口。
- 仅访问已支持新闻站的入围详情，提取页面明确给出的时间和最多 1800 字正文摘录；不得用 URL 日期、聚合日期代替新闻时间。未知时间仅作为线索保留，不直接进入正文候选。
- 同一事件保存单一代表，按时间证据、来源可靠性和材料完整度优先，其他报道的标题/链接/来源保存在元信息；历史落库记录不删除。
- 采集策略标记为 `hot_featured_v1`，旧版全量采集记录保留但不在生产生成中直接复用；新策略首次生成会补采。
- 主编前由模型筛选、程序限制国内/国际各最多 10 条；热榜不可用时保留精选补充并在正文披露降级，不能静默以旧榜或旧新闻补位。

LIVE 只读冒烟（2026-11-11）：新适配器取得国内/国际各 20 条，实际榜单日期分别为 11-10/11-11；精选取得国内 4 条、国际 5 条，均有页面时间和正文摘录。未写入生产库、未调用模型；该结果不代表长期稳定性验收。

### 4.3 热摸爽：发现热点，不当作精确时间的主证据

专项验证汇报记载：每日早报与快照 Markdown 约 30 条热点，含 AI 摘要与原始链接；其统计周期是 **05:00–05:00**，不是晨报的 08:00–08:00。部分条目缺原始发布时间，不能将批量相同的 Feed 时间戳当作每条新闻发布时间。

因此热摸爽用于**补充事件线索、发现不同平台关注点与跨源核对**；纳入正文时仍需通过原始来源或可信时间记录确认属于本期。优先使用公开 MD/RSS，不依赖可能面向站内的私有 `api/*` 路径。

### 4.4 国内与国际的风险差异

国内组合以新浪热榜及中新网有限精选为主，但热度聚合可能遗漏财经和低热度政策新闻；国际组合虽然可利用中新网国际与时政报道，但仍主要来自国内报道视角，**独立英文权威来源的交叉核验不充分**。

此前专项汇报中的 **5/5 重大事件命中**仅是单日五事件小样本，不能当作长期覆盖达标。GDELT 曾出现 429，BBC 等站点曾在本机不可达，GNews 免费层存在延迟/配额限制。这些不是决定重新恢复六时点采集的充分理由，但属于上线前来源覆盖和事实核查的检验事项。

### 4.5 来源留存与数据授权

- 记录文章/事件 ID、聚合来源、原始来源、原始链接、发布时间、发现/获取时间、内容缺失、核验状态及快照版本。
- 对 AIHOT 的合理私有缓存、撤回/删除/更正义务与第三方原文授权分别核查；不默认全量镜像长期保存合法。
- 对中新网网页、热摸爽 Markdown 与其他原站内容分别核实自动化访问和摘录/保存许可。
- 资料无法合法长期保存全文时，优先保留允许的元数据、原始链接及自有分析/晨报正文；不因为技术索引需要就越过授权边界。
- 如果来源或证据不足，应明示覆盖/核查缺口，严禁编造原文和独立交叉核验结果。

## 五、历史检索、去重与四种复用机制

### 5.1 分层去重

1. **精确相同**：规范化 URL、标题或正文内容哈希。
2. **高度近似**：SimHash / MinHash 等指纹用于发现可能的转载与轻改写。
3. **同事件归组**：结合语义、时间、主体、事实和事件发展识别多源报道。

只自动归并**高置信的重复文章**。同一事件出现新时间点、新版本、新证据、反转或重大更正时保留独立记录；事件归组不能等于不可逆删除原始文章。

### 5.2 统一 RAG Tool

- Qdrant 两类历史资料支持 Dense + BM25 等混合检索，结合发布时间、来源、报告版本等条件筛选。
- **三个 Subagent 都可使用**；按需 Query 改写/扩展、补充检索或 Rerank，而非每次强制全链路。
- Query 改写应保留原问题，不擅自引入不存在的事实；Rerank 提高候选排序，不等于给事实打真实性分。
- 增强组件异常可回退基础检索，但**必要索引不存在或不一致不能通过“回退”绕过阻塞规则**。
- T21 的实际收益与 Reranker 最终实现需要真实样本对照；以前的 PARTIAL 不能自动改成上线通过。

### 5.3 四类机制的区别

| 机制 | 用途 | 生命周期及限制 |
| --- | --- | --- |
| **阶段结果缓存（本地持久）** | 普通分析节点和三个 Subagent 的**成功输出**跨重试复用 | 最长 **12 小时**，每天 08:00 清理上一轮；按输入快照、模型、Prompt、个人上下文、检索策略等依赖判断有效性 |
| **LangGraph Checkpoint** | 一次工作流中断、重启后恢复状态 | 是执行恢复机制，**不等于**跨运行结果缓存 |
| **服务商 Prompt 缓存** | 重复提示词前缀带来的模型侧加速/计费变化 | 按服务商返回字段观察；未命中或未返回不可推断为缓存故障 |
| **Embedding 复用缓存** | 同一文本/分块与相同模型条件下复用向量结果 | 与 12 小时阶段缓存**独立**；文本、分块、预处理或模型版本变化必须重新计算 |

SQLite 可承载本地持久阶段缓存，Qdrant 已有有效向量可优先复用；**没有当前证据要求为 V2.0 强行新增 Redis**。更换组件不自动解决快照污染、缓存失效或并行重跑的幂等性问题。

当资料、个人上下文、配置或检索策略变化时，仅复用确证仍有效的阶段；无法确定依赖时重算。最终报告整合在重新生成时应重做。缓存删除不可影响长期资讯、正式日志与历史报告。

## 六、模型与评分的实现口径

### 6.1 模型接入

- **正式自动晨报**：规划使用 DeepSeek V4.1 Flash，API 模型标识为 **`deepseek-flash`**；按已确认允许时段在**每次调用前**校验，禁止在不允许的时段静默继续，禁止自动切换到未经批准的模型。
- **开发和手动重新生成**：沿用既有 DashScope 可用模型的配置原则；具体可用模型和免费额度应以实际环境状态为准。
- **独立质量评价**：使用独立模型调用；只输入最终报告正文，其身份与主生成调用分开记录。
- **检索增强所需 LLM / Reranker**：明确调用来源与资源消耗，不能因增加 Query 改写而暗中改变供应商或正式模型许可策略。

V0.5.2 明确记载 T8 的真实调用、JSON、Tool Calling、Streaming、Token/费用字段已通过，可按其**专项实调汇报**将 T8 更新 PASS。本次编制未读取相关结果 JSON，**不虚构具体 HTTP 响应、Token 数或成本数字**。短输入尚未观察到 Prompt 缓存命中不等于 API 连接失败。

关于 Thinking：最新问题清单要求节点级显式配置并测试，具体参数行为仍由接入层按官方接口和实际验证适配，不把测试探针的设置无条件写进产品文案。

### 6.2 D03：质量综合分的具体决定

**V0.6 采用固定等权方案（用户已授权自行确定，无须再次确认）：**

- 五个维度均为 0–100 分，权重各 20%。
- `综合分 = (资讯呈现 + 内容逻辑与一致性 + AI 技术分析 + 个人总结与建议 + 阅读体验) / 5`。
- **先校验每个分项范围与类型，之后由程序计算综合分**；最终整数采用通常的**四舍五入（0.5 向上）**，避免评价模型提供的“综合分”与分项计算冲突。
- 评分口径版本建议固定为 `quality_score_v1`，保存报告版本关联；未来若改规则，需要变更规则版本并说明历史分数可比性。
- 质量分只是内容表达质量的参考，不代替事实核验；不设强制合格线，不因低分自动重生成。
- 仅正文的评价不能可靠验证重大新闻是否遗漏、引用是否真实或个人行为是否属实。2026-11-11 用户确认移除独立事实校验，不再执行该路径或以其结果阻塞发布。

这是本次**编制时作出的实施口径选择**，符合 T18 汇报推荐等权及用户授权；不声称已通过新的独立统计实验。

### 6.3 统计字段与计费

记录节点/Agent、模型、调用开始与结束、请求结果、Token 输入/输出、模型提供的推理 Token、Prompt 缓存命中/未命中（如存在）、耗时、可估算费用与相关价格版本。阶段缓存与 Embedding 复用另行计数，不能混进 Prompt Token 命中率。

如果模型不返回某字段，展示“未知／不可得”，不能推断为 0。用户未要求严格的每轮费用上限，不以控制 Token 为理由牺牲明显重要的资讯与证据；但必须遵守模型上下文能力边界。

## 七、故障、版本与一致性边界

### 7.1 关键阻塞／可降级区分

| 故障 | 产品与技术处理 |
| --- | --- |
| 新闻源超时或个别原文缺失 | 有可靠剩余证据时可以降级；记录来源缺口，不把失败写成“无新闻” |
| 本期必要 AI 资讯索引或历史晨报索引失败 | **必须阻塞进入 Agent 分析**，有限重试并保留错误状态 |
| 普通分析节点失败 | 视影响允许降级，不能编造未完成节点结果 |
| 技术研究或目标分析失败 | 建议只可依据实际有效的上游结果；降级必须明示 |
| 建议 Subagent 失败 | 明确标记建议生成失败，不等于 0 条建议 |
| 主编无法形成完整报告 | **阻塞发布** |
| 独立质量评价 API 失败 | 报告可发布，评价为未评价或失败 |
| LLM 超时/限流/拒绝 | 记录并有限重试，不隐式更换模型 |

自动生成最多自动重试 **3 次**；手动重试不设总次数上限，但同日避免重复并发运行。上述次数来自 V0.5 原设计，非新提案。

### 7.2 数据版本与主报告唯一性

- 每日一个主报告身份；当日自动报告失败且尚无主报告，首次手动成功结果成为主报告，之后成功的重新生成是附加版本。
- 每次生成使用可追溯的**冻结快照**；冻结后新来的新闻和个人记录不能静默进入当前运行。
- 缓存按完整输入依赖判断有效，错误缓存可主动失效；同一工作流的重试、恢复及并行阶段必须防止重复写入正式主报告。
- 历史报告版本、引用、评价、执行日志和索引状态保持关联；旧报告不因为用户计划或个人记录后来变化就自动重写。
