# Personal Hub 路线图（ROADMAP）

版本：v1.0（规划稿）
定位：**本文档是 V1.0 之后版本规划的唯一权威来源。**

## 1. 文档分工与规则

| 文档 | 管理范围 |
|---|---|
| `Docs/DEVELOPMENT_PLAN.md` | 仅管理 **V1.0** 的开发任务与验收标准 |
| `Docs/ROADMAP.md`（本文档） | 管理 **V1.0 之后**确定实现或待评估的功能 |
| `Docs/PRD.md` | 定义 V1.0 需求、非目标与验收；引用本文档 |
| `Docs/ARCHITECTURE.md` | 对影响 V1.0 架构的未来需求，仅保留必要**设计约束**，不提前实现 |

规则：

1. ROADMAP 中的功能**不纳入 V1.0 开发与验收范围**，未经用户明确批准不得提前实现或排入当前开发计划。
2. ROADMAP 只记录需求方向与评估状态，**不创建未来版本的详细技术实施任务**；进入某个版本的实施细节，在该版本启动时再行规划。
3. 若未来需求会影响 V1.0 架构，只允许在 `ARCHITECTURE.md` 追加设计约束（如"接口不得依赖 Windows 特有对象"），约束服务于"不堵死未来"，而不是提前建设。

## 2. V2.0 已确定需求

### 2.1 移动端支持（已确定）

- **目标**：手机访问 Personal Hub，含必要的身份认证与安全连接（HTTPS）。
- 演进路径（设计约束级，V1.0 已预留）：局域网访问（绑定 `0.0.0.0` + Bearer Token）→ HTTPS（反代或自签证书）→ 移动端数据同步（SQLite 单写者约束下，服务端为唯一写者，移动端为纯 API 客户端）。
- **待定项**：具体形态——PWA、手机浏览器访问电脑端服务、还是独立移动客户端（Android/iOS），启动 V2.0 时再评估，本文档不预先定论。
- V1.0 必须遵守的约束：前后端彻底分离、全部业务经 API、响应式布局、数据结构与接口不依赖 Windows 前端特有实现。

### 2.2 备份与恢复（已确定）

- **目标**：完整备份与恢复能力，覆盖：
  - SQLite：应用库 hub.db + 聊天两库（原始快照、归一化）；
  - Chroma 向量索引目录；
  - 笔记附件：`data/reading_notes/` 下的云记导出文件；
  - 应用配置：`llm_config.json`、来源配置（news_sources）、设置项（.env 中的非密钥结构说明，密钥本身不备份）。
- 方向：SQLite online backup + 目录打包，恢复为离线操作（停服务→解包→校验→启动）。
- 与移动端同步服务**一并设计**（跨端场景下备份价值最大）。
- V1.0 的过渡保障（已在 PRD §2.6 强制执行）：开发/测试用隔离副本，真实库不可逆操作需用户批准。**该规范在 V2.0 备份上线前一直有效。**

## 3. 待评估需求池（未排期、未承诺）

以下功能曾出现在讨论中，**均未承诺实现**，进入任何版本前须经用户批准并补充评估：

| 需求 | 说明 | 来源 |
|---|---|---|
| OCR / AI 阅读笔记总结 | 云记笔记的 AI 处理 | V1.0 非目标 |
| 云记实时同步 / 双向编辑 | 与云记深度集成 | V1.0 非目标 |
| AI 自动规划 | 根据历史与计划自动生成每日安排 | V1.0 非目标 |
| 复杂提醒 | 通知、定时提醒 | V1.0 非目标 |
| GitHub Trending 接入 | 无官方 API，方案脆弱 | PRD §6 风险 |
| RSSHub 扩展资讯源 | 自部署/公共实例 | PRD §2.2 |
| 多用户 / 权限体系 | 家庭共用等 | V1.0 非目标 |
| Electron 桌面壳 | 独立窗口体验 | V1.0 非目标 |
| 新闻 LLM 摘要 | 每篇调 LLM，成本高 | V1.0 非目标 |
| 计划/笔记多端离线编辑 | 离线场景同步冲突 | 移动端衍生 |

## 4. 需求进入流程

1. 新想法 → 先记入本文档"待评估需求池"（或对应版本的已确定区，由用户裁定）。
2. 用户批准后 → 提升为某版本的已确定需求；若影响 V1.0 架构，在 `ARCHITECTURE.md` 追加设计约束。
3. 版本启动时 → 在该版本的 PRD/DEVELOPMENT_PLAN 中定义详细需求与任务（V2.0 的详细规划文档届时新建）。
