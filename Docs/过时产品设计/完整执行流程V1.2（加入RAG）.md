# 今日晨报｜完整执行流程 V1.2

**整体架构：编排式工作流 + 普通 LLM 节点 + 固定调用的三个 Subagent + RAG 混合检索**

**前置条件（独立于每日晨报生成）：**资讯采集模块定时获取新闻并写入本地数据库；新增或更新的 **AI 技术资讯**建立/更新向量索引。已生成的**历史晨报**建立独立向量索引。原始新闻、个人记录及完整晨报以原始数据库为准；向量索引用于发现相关历史内容，不替代原始数据。

## 执行规则

1. **三个 Subagent 固定调用**：技术研究与目标分析并行，建议 Subagent 必须等待两者返回后执行；主 Agent 不再决定是否启动它们。
2. **固定调用不等于强制生成结论**：技术资讯不足时，技术研究 Subagent 可返回“无值得深入研究的进展”；没有适当行动时，建议 Subagent 可返回“无新增建议”。
3. **RAG Tool 由 Subagent 在任务中调用**：数据准备阶段不预先执行历史向量检索。Subagent 自主决定查询内容、是否追加检索和分析深度；是否存在重要历史关联应主动检查，但不要求每次多轮检索。
4. **两类向量索引**：技术资讯和历史晨报分别维护索引，通过统一检索工具访问；对检索命中的历史晨报应回溯原始来源，避免将旧的 AI 总结当作事实。
5. **不改变既有数据边界**：个人助手数据库只读；资讯由独立采集流程预先落库，Subagent 不能绕开本地数据直接进行未留痕的互联网研究。

## 相比 V1.1 的主要变化

- 删除数据准备阶段的“准备历史检索能力（Tool / RAG）”步骤；保留 Subagent 可自主调用的 RAG 检索工具。
- 将“按需调用三个 Subagent”改为“**每日固定调用三个 Subagent**”。
- 明确**技术研究和目标分析并行，建议分析在两者之后执行**。
- 主 Agent 主要承担报告整合，不再承担是否启动核心 Subagent 的触发判断。
- 保留原六阶段流程和技术资讯、历史晨报两类向量库设计。
