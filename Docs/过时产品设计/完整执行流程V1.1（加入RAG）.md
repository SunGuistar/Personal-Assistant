# 今日晨报｜完整执行流程 V1.1

**整体架构：编排式工作流 + 普通 LLM 节点 + 按需 Subagent + RAG（向量检索）**

**前置条件（独立于下方晨报生成流程）：**资讯采集模块持续将新闻写入本地数据库；其中 AI 技术资讯在入库或更新后同步建立/更新向量索引。历史晨报在生成成功后建立向量索引。两类索引分开管理，统一通过检索工具使用；原始事实和完整报告仍以本地数据库为准。

```text
每天 08:00 自动触发
│
├── 1. 数据准备（Tool）
│   ├── 读取本地资讯数据库
│   │   ├── 国内社会新闻
│   │   ├── 国际社会新闻
│   │   └── AI 相关资讯
│   │
│   ├── 读取个人助手数据库（只读）

│   │   ├── 每日任务
│   │   └── 长期计划（重点关注标红计划）
│   │

│   │   ├── 资讯兴趣偏好
│   │   ├── 行动建议偏好

│   │

│       └── 统一检索入口（关键词 + 向量检索，按需返回原始记录）

│   │
│   ├── 资讯分析节点

│   │   ├── 个人兴趣匹配
│   │   ├── 新闻筛选与排序
│   │   └── 新闻摘要
│   │
│   └── 个人分析节点
│       ├── 昨日活动总结
│       ├── 任务完成情况分析
│       └── 重要计划进展分析
│

│   ├── 汇总资讯分析与个人分析结果

│   │
│   └── 调用 Subagent

│       │   ├── 比较历史技术与最新进展，分析应用价值
│       │   └── 返回研究结论及依据

│       │   ├── RAG 检索历史晨报中相关目标与进展线索
│       │   ├── 识别目标之间的关联和冲突
│       │   └── 返回目标分析结论及可核实依据
│       │

│           ├── 综合资讯、个人目标和昨日总结

│           ├── 结合行动建议偏好
│           ├── 判断建议是否重复、过时或已完成

│   ├── 检查建议是否有对应依据
│   ├── 检查报告结构与完整性

│
└── 6. 输出与保存（Tool）
    ├── 保存今日晨报及历史版本（本地数据库）
    ├── 保存主要引用与历史关联依据
    ├── 记录生成时间
    ├── 记录 Agent / Subagent 执行情况
    ├── 记录 Token、缓存和费用

    └── 为成功生成的晨报建立/更新向量索引
        ├── 按资讯事件、昨日总结、建议等语义单元分块
        └── 关联晨报 ID、日期及原始依据
```

## 补充说明

- **RAG 的用途**：联系此前的 AI 技术资讯和历史晨报，而非替代当天新闻查询、任务统计或现有 Memory 读取。
- **数据关系**：本地数据库保存原始资料与晨报；向量库保存语义检索索引。技术资讯与历史晨报使用不同集合，通过统一检索工具访问。
- **事实约束**：历史晨报中的 AI 分析不能直接当作原始事实；涉及事实时回溯源新闻或当前个人记录。
- **范围未变**：保留原文件的六阶段流程、两条并行普通 LLM 分析节点，以及技术研究、目标分析、建议三个按需 Subagent。
