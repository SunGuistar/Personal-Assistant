## 3. 时效性测量

- **中新网归档（LIVE，PASS）**：分钟级 `dd_time` 时间戳；窗口最早条目 08:02、最晚 07:42，**完整覆盖 08:00–08:00**；14:24（窗口后 6h）抓取不丢内容；08:00 失败任意时刻重试均可回溯（冻结内容）。时间戳为发布时间（页面口径），非采集时间。
- **热摸爽（LIVE，PARTIAL）**：统计周期 05:00–05:00 与晨报窗口错位；条目无原始发布时间（已知问题，上一轮已记录）。
- **GDELT（LIVE，PARTIAL）**：本轮重试：首次 429（16s），等待 30s 后二次请求成功（HTTP 200，18.9s 返回 25 条 `sourcecountry:US` 文章），稳定性依旧差但可重试成功；仅标题级元数据。
- **天聚 world（BLOCKED）**：文档无时间过滤参数，"08:00 单查 + ctime 本地过滤"方案理论上可行（字段含分钟级 ctime），但**窗口早期内容能否深翻页取回、新闻延迟多久入库均未实测**，是主要待验证缺口。
- **聚合/天聚简报（BLOCKED + 结构性 FAIL）**：mtime 日期级，无法做 08:00 逐条过滤，结构性不满足窗口口径。

## 4. 数据质量与可追溯（LIVE 抽查）

- 中新网国际条目均带原文链接（`chinanews.com.cn/gj/...`），可回溯；44 条中无重复标题。
- 热摸爽 30 条均带原始来源链接（含 NYT 中文、腾讯/新华社等），摘要与原始报道一致（抽查 I1/I4 两条，事实一致）。
- 天聚 world 字段含 url+source+ctime（STATIC），可追溯性设计上成立，实测 BLOCKED。
- 聚合/天聚简报 digest 无原文链接 → 无法追溯，**不满足晨报"事实可核实"底线**，只能做覆盖检查信号。

## 5. 组合增益评估

- 中新（全栏目）与热摸爽在该窗口**完全互补**：各自 3/5，漏集不相交（I2/I3 vs I5），并集 5/5。
- 组合暴露的共同盲区：I3（俄副外长表态）两者皆漏——说明"对美伊话题覆盖强、对俄欧安全表态覆盖弱"的结构性倾向，单日样本，需多日观察。
- 与上轮结论一致：缺独立英文权威源交叉核验（BBC 不可达），国际版块事实核查链仍不完整。

## 6. 结论

1. 免费可实测的国际源中，**中新网归档 + 热摸爽组合仍是唯一实测可用方案**（本轮再次验证，且国际栏目识别稳定）。
2. 国内 API 路线（天聚/聚合/顺为）因无 Key 全部 BLOCKED；其中聚合类简报**结构上**就不满足主源要求。
3. 若用户愿意注册天聚免费 Key，最值得复测的是 world/index 的"深翻页回溯窗口早期内容"能力——这是国内 API 路线能否成立的唯一关键未知。
