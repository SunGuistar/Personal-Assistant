> 日期：2026-11-10；执行：V2 工作区（`E:/wechat-LangGraph-v2`，分支 `feature/V2`）；环境：Conda `agent`（Python 3.13），Windows，本机直连国内网络无代理。

## 0. 总体结论

**国内 API/MCP 路线未能形成可替代方案**：三个 Key 类候选（天聚 world、聚合简报、顺为）全部因无凭据 BLOCKED，唯一完成实测的是免费的中新网国际归档（再次 PASS）。天聚数行存在**授权层面的实质阻塞**（"不得用于终端展示"），在未获得用户/官方确认前不能上线。国际新闻来源结论与上一轮保持一致：**中新网归档 + 热摸爽组合 + GDELT 辅助**，取消四小时采集的条件仍不成立。

## 1. 12 项必答问题

**1. 最适合的国内国际新闻 API 是哪一个？**
实测层面唯一答案是**中新网按日归档页**（非 API，HTML 解析，免费无需 Key）：44 条国际/窗口、分钟级时间戳、可完整回溯（LIVE，`results/chinanews_world_window.json`）。天聚 world/index 端点有效但数据实测与授权均 BLOCKED。**结论：没有实测通过的"国内国际新闻 API"。**

**2. 最适合的来源组合？**
中新网归档（国际栏目 + 时政栏目合并过滤，本轮 I4 事件在时政栏目，仅看国际栏目会漏）+ 热摸爽每日早报（LIVE 并集 5/5）；GDELT 做发现与回溯辅助（429 退避，本轮重试成功）。与上轮结论一致，本轮新增"时政栏目必须纳入"的修正。

**3. 是否需要 API Key？**
中新网归档：不需要。天聚/聚合/顺为：需要（注册获取，任务书禁止代注册，故 BLOCKED）。

**4. 免费额度是否够用？**
天聚普通会员免费 100 次/天、QPS 3（STATIC）——每天 08:00 查询 1–5 次，额度足够。但"额度够"不等于"可用"：授权问题未解决（见第 9 问）。

**5. 24 小时时间窗口能否完整覆盖？**
- 中新网归档：**PASS**（LIVE：最早 08:02 / 最晚 07:42，跨两天拼接，窗口后 6h 重取不丢）。
- 天聚 world：**BLOCKED**——字段含分钟级 ctime 但无时间过滤参数，只能靠 08:00 深翻页后本地过滤，窗口早期内容能否取回未实测，是关键未知。

**6. 国际重大新闻覆盖情况如何？**
单日窗口 n=5：中新全栏目 3/5、热摸爽 3/5、组合 5/5（LIVE，`results/coverage_hits.json`）。样本量小，不得外推。天聚/聚合覆盖 BLOCKED。聚合类简报（聚合数据/天聚 bulletin）**结构性不满足**主源要求（无 URL/来源/逐条时间）。

**7. 是否能追溯原始新闻？**
中新网：条目均带原文链接，可回溯（LIVE 抽查 44 条）。热摸爽：带原始来源链接（含 NYT 中文），抽查 2 条摘要与原文一致。天聚 world：字段设计含 url/source（STATIC），实测 BLOCKED。聚合简报：**不能**（无链接）。

**8. REST API 与 MCP 哪个更合适？**
**REST API**（`mcp_vs_rest.md`）：MCP 经实测确认为同一 REST 数据的包装，无额外能力；定时批处理任务用 REST 在确定性/可测试性/故障处理上全面占优。

**9. 数据授权是否满足私人晨报使用？**
- 中新网归档：无公开 API 条款，公开页面低频抓取，自担合规风险（与上轮一致）。
- 热摸爽：要求保留来源链接，有删除通道（上轮已核）。
- **天聚：官方明示"仅限用于内部数据分析和机器学习，不得用于终端展示"**。私人中文晨报是否属于"终端展示"存在实质不确定性——**必须用户阅读条款并决定，或由用户向官方书面确认；验证方不自行认定授权**。叠加新闻版权（内容来自中华网等媒体），"生成摘要再展示"的授权链不完整。
- 聚合/顺为：条款需注册后可见，BLOCKED。

**10. 能否取消每四小时采集？**
**不能（维持上轮结论）**。理由：① 国内 API 路线全部 BLOCKED，实测国际源仍只有"中新网归档+热摸爽"组合，缺独立英文权威源交叉核验；② 唯一有潜力的天聚 world 卡在授权确认与窗口回溯两个未验证项；③ 覆盖率证据（5/5）是单日小样本，不足以支撑调度级决策。**若用户后续确认天聚授权并复测通过，可重新评估"每日 08:00 一次 + 失败重试"（归档式回溯使单查方案天然可靠）。**

**11. 是否存在上线前必须解决的问题？**
- **阻塞上线**：天聚授权确认（若走天聚路线）；中新网归档页结构监控（HTML 解析，结构变更即失效，需告警）。
- **阻塞开发决策**：是否注册天聚/聚合免费 Key（需用户操作）；注册后的复测清单：
  1. world/index `num=50` 连续翻页至 ctime < 窗口起点，记录可达深度（验证问题 5）；
  2. 对照 `fixtures/reference_events.json` 跑 3–5 个不同日期窗口的覆盖率（验证问题 6）；
  3. 检查返回 source/url 字段实际填充率与链接可达性（验证问题 7）；
  4. 确认免费额度下每日 5 次调用是否稳定（验证问题 4）。

**12. 对 V0.5 和 D01 最小的修改是什么？**
本轮**不改任何产品文档**（任务约束；且 D01 文件在本仓库不存在，实际位于 main 工作区 `Docs/` 与否需用户确认）。待用户决策后建议的最小修改：
- 国际来源清单中"中新网归档"一项注明"国际+时政两栏目合并过滤"；
- 若天聚授权通过：D01 国际分支增加子决策"天聚 world 每日 08:00 主查 + 中新归档兜底"，并取消四小时采集；
- 若授权不通过：维持上轮方案 D（每日聚合 + 一次 20:00 补充），文档不变。

## 2. 方案 A/B/C 比较（任务书第五章）

| 维度 | A 维持 4h 采集（中新归档+热摸爽） | B 每日 08:00 国内 API 聚合（天聚 world） | C 每日 API 聚合 + 少量补充 |
|---|---|---|---|
| 当前可落地性 | ✅ 全部源实测可用 | ❌ 授权未确认 + 窗口回溯未实测 | ❌ 依赖 B 成立 |
| 窗口覆盖 | PASS（归档回溯） | 未知（BLOCKED） | 未知 |
| 国际覆盖（样本） | 组合 5/5 | BLOCKED | BLOCKED |
| 事实核查链 | 弱（无英文权威源，BBC 不可达） | 中（源媒体链接，若实测填充） | 中 |
| 调度复杂度 | 高（6 时点） | 低（1 次/天） | 中 |
| 授权风险 | 低（自担合规） | **高（"不得终端展示"）** | 高 |
| 请求量/天 | 6×2 源 | 1–5 次 | 数次 |

**回答必答问题："如果国际新闻主要从国内 API 获取，是否可以取消原来的每四小时采集？"——理论上可以（天聚 world 支持翻页+ctime 过滤，08:00 单查+失败重试即可，归档式回溯不丢窗口），但前提是授权确认 + 窗口回溯复测通过，两者目前都未满足。**
