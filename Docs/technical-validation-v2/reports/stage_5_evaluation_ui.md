# 阶段五报告：质量评价、实时日志与 UI 可行性（T17、T18）

## T17（PARTIAL：SSE 链路实测通过，正式 UI 未动）

实测（独立 FastAPI + sse-starlette 探针，端口 8634，测完即关）：

- 事件流携带节点归属 + 时间戳 + 技术详情（模型/Token/工具/耗时），无私人原始数据与密钥。
- **并行事件**：技术研究/目标分析双线程交错推送，客户端收到的事件流交错且归属正确（`parallel_events_interleaved: true`）。
- **断线重连**：Last-Event-ID 续传，重放该 ID 之后的事件，无重复（resumed 6 条）。
- **刷新恢复**：历史查询接口返回全部 7 条持久化事件。
- 前端现状（STATIC）：React 18 + Tailwind，8 个页面（Home/News/Plans/Reading/Wechat/Github/Cleanup），`web/src/api/*.ts` API 客户端模式成熟；**无既有 SSE/WebSocket 先例**；sse-starlette 已在后端依赖。
- SSE vs WebSocket：SSE 单向推送足够覆盖日志场景、EventSource 原生自动重连、与 FastAPI 集成 5 行代码；WebSocket 需自管心跳重连，收益有限。**推荐 SSE**。
- PARTIAL 原因：按约束未修改正式 UI，三个二级页面（晨报正文/质量评价/历史晨报）的状态管理、历史版本切换、阅读宽度等需在开发期实现并走设计走查。

## T18（PASS，LIVE：qwen-flash × 9 次真实调用）

- 只传最终晨报正文（fixture 三份匿名样本：高质量/普通/明显逻辑问题），五维+综合分+自然评价 9 次调用全部结构化成功。
- **区分度**：综合分 88 / 36 / 20，梯度合理；低分样本的评价文本指出了自相矛盾与来源缺失。
- **波动**：temperature=0 下三次评分波动 ≤2 分（高分 87–88，低分 20–22）。说明在固定参数下稳定性好；生产如需观察真实波动应固定温度并记录多次评分分布。
- **失败路径**：模型标识不存在时评价调用失败，报告记录"未评价/评价失败"，正文保留。
- **综合分公式对比**（三份样本均值，三种方案）：等权 / (0.25,0.25,0.2,0.2,0.1) / (0.15,0.35,0.2,0.2,0.1)。结果差异在 1–3 分内（见 results/t18_quality_eval.json）。
- **推荐（待产品确认，不作为既定规则）**：采用**等权平均**——最可解释、最稳定、与五维展示一致；若后续发现"逻辑一致性"对阅读体验影响更大，再考虑固定轻加权并版本化。
